  `glb-viewer-core` as a dependency (DESIGN.md 2.3 and 2.4). Its inspection logic is ported.

## Phase 1: Foundation

1. **Tokens** (`tokens.css`): the ink, blue, now and state ramps; type scale (13 px base);
   radii; motion tokens; two densities (DESIGN.md 6). Old tokens are removed, not aliased, so
   leftovers fail visibly.
2. **Extract the viewer core** into `src/viewer/core/`: lighting rig (studio environment from a
   tiny procedural scene through PMREM), background gradient, fog, ground grid, selection outline,
   framing helpers, picking. Rule enforced by a lint boundary or a unit test: nothing in
   `src/viewer/` imports from `react-router-dom`, `src/api`, `src/auth`, or `@tanstack/*`.
3. **The Stage** (`src/stage/`): one root `<Canvas>` (`fixed inset-0`), `StageProvider`, a view
   registry with the `StageView` contract (DESIGN.md 4.3), and the transition clock (4.4) that
   exposes `--view-p` to CSS and `p` to the scene. Interruptible, with reduced-motion cuts.
4. **The Trace** (4.2): points, ribbons, grid, drift, parallax, pause when hidden, static frame for
   reduced motion, and the no-WebGL / context-loss fallback.
5. **Preloader** (4.5): the stage-level progress marker and the tiered loading states.

**Done when:** a blank route shows the Trace behind an empty page; navigating between two stub
views moves the camera on one clock; killing the WebGL context shows the fallback and restores.
GPU time of the Trace measured and recorded (target under 1.5 ms; if it misses, the point count is
reduced and the number is written down).

### Phase 1: what was built, and where it differs from the plan

Built: new tokens (renamed everywhere, no aliases); `src/viewer/core/` (palette, glTF parse and
dispose and framing, atmosphere, studio environment, ground, selection outline); `src/stage/` (store,
`useStageView`, transition clock, camera rig, the Trace, host with fallback and context-loss handling,
preloader, dev lab at `/_stage`, and the downloader that joins the API to the viewer). The old
per-view `Stage` is kept, rebuilt on the core pieces, until Phases 3 and 4 remove it.

Differences from the plan, and why:

- **Boundary check is a test, not a lint rule.** `src/viewer/boundary.test.ts` fails if anything
  under `src/viewer` imports the router, TanStack, the API or any app layer. `loadScene.ts` had to be
  split to pass it: parsing stays in the core, downloading moved to `src/stage/sceneSource.ts`, and
  `ScenePreview` moved out to `src/pages/scene/`.
- **GPU time was not measured.** This machine renders WebGL in software, so the lab shows CPU-side
  frame times and draw-call counts only (the Trace is 5 draw calls, about 27,000 line vertices and
  about 1,900 points, with all motion computed on the GPU). **Please read the lab's frame cost on
  your own GPU (`npm run dev`, then `/_stage`).** The Trace steps its curve count down by itself if
  frames run long; that logic ignores the first 1.5 s, single frames over 200 ms, and needs two slow
  windows in a row, after a first version stepped down on the startup hitch.
- **The Trace was reworked after the first screenshots**: sparse near-straight scratches became
  longer, curlier ribbons with keyframe dots along them.
- **The grain overlay was removed.** It is not in the new design, and a full-screen SVG-noise layer
  made software compositing take 12 to 30 s per frame under an animated gradient.
- **A real bug was found and fixed by a test:** an interrupted camera move landed a rounding error
  short of its target.
- **The dev mock and screenshot tooling** (`dev/`, `npm run mock`, `npm run shots`,
  `dev/stage-shots.mjs`) were added in Phase 0 as planned. `playwright-core` is a pinned dev
  dependency. `idb-keyval` is not installed yet; Phase 3 adds it.

### Phase 2: what was built, and where it differs from the plan

Built: `src/stage/Chrome.tsx` (floating variant for browse views, one-line variant for the player, a
`trailing` slot for the recording indicator that Phase 3 fills, and a skip-to-content link),
`src/ui/Breadcrumb.tsx` (last two crumbs on phones, no wrapping, no stray separator), the sign-in and
register pages on the full-strength Trace, and `dev/auth-flow.mjs`, which walks every auth flow.
Verified: 24 of 24 checks pass against the mock, covering deep-link return, wrong password, taken
address, password rule, keyboard order, Enter to submit, sign-out, expired session, redirect when
already signed in, phone layout, and the stage fading when a window is resized across the phone
breakpoint.

Differences from the plan, and why:

- **The Stage creates its canvas on first use, not at startup.** The phone sign-in is meant to use a
  static gradient; the first version relied on a never-drawn canvas being transparent, which is not
  reliable. Now no WebGL canvas exists at all until a view wants to draw (0 canvases on a phone
  sign-in, checked), and pages that do not use the Stage yet spend no GPU work.
- **A check of mine was wrong, and I fixed the check, not just the code.** It read an empty value as
  zero and passed; it now reads the real opacity and the canvas count.
- **`AppShell` is still here, temporarily.** It now wraps `Chrome` and still paints the old opaque
  page backdrop, because browse pages move onto the Stage in Phase 3. It is deleted then.
- **A skip-to-content link was added**, which the plan did not list; it is the first focus stop.
- **Still manual:** a screen reader has not been tried, only keyboard order and focus visibility.

## Phases 3 to 7: what was built, and where it differs from the plan

- **Lobby budget** is 13 requests, not 9: each of the four newest projects needs its detail and the session list of its latest scene (1 + 4 + 4x2).
- **Framing** uses `fill` (the smaller side of the free region over the canvas height, `regionFill`) rather than an aspect ratio; the aspect version framed wrongly with panels open.
- **Camera continuity** between Scene and Session is a `framedKey` in the Stage store: the camera is only re-framed when the scene version differs, or when leaving a tool view for the Trace.
- **Scene cache** (`sceneAssets.ts`) is reference counted and keeps two idle scenes. The player animates a clone (`SkeletonUtils.clone`); the inspector shows the master read-only.
- **Panels**: docked tabs, floating windows and a rail, remembered per view kind in `moodyblues.panels.v1`. On a phone the dock stacks above the timeline. The dock's tab strip scrolls horizontally when it is too narrow.
- **Glyphs**: summary form from the session record; timeline form from the replay, cached in IndexedDB (`moodyblues-glyphs`, key `id:replaySizeBytes:keyframeCount`); "Index sessions" is opt-in. No Web Worker was needed (nothing parsed for more than 50 ms on the fixture).
- **Snapshots** live in their own IndexedDB (`moodyblues-snapshots`); the default shared store failed when another script created an empty database. Capture code is in `snapshotCapture.ts`, apart from `snapshots.ts`, so the lists do not pull three.js into the first bundle (the first build had; the first bundle is 136.6 kB gz, three.js is not preloaded).
- **Grain overlay removed**: it froze software compositing and did little visually.
- **Inspector**: panels are Hierarchy, Materials, Textures, Geometries, Stats and Raw. Texture previews use a canvas for decoded images and a render target for GPU-only textures (`?thumbnails=gpu` forces it).
- **Debug panel**: `?debug` (remembered, `?debug=0` clears), lazy. Toggles are wireframe, axes, bounds, show inactive and fog; the planned "effects" toggle was dropped because there are no effects to turn off.
- **Hardening**: `StageNotice` explains a missing WebGL context or a lost one in the tool views; contrast of every text token against every surface is checked from `tokens.css` (all >= 4.5:1); tab order and Enter-to-select verified in the inspector.
- **Removed**: `shell/AppShell.tsx`, the per-view `viewer/Stage.tsx` canvas.
- **Not verified**: GPU frame times (software WebGL only), real KTX2 textures, screen readers, and the cold-load behaviour of a production build.

## Checks, every phase

`tsc -b` strict, `oxlint`, `vitest run`, and a dev-server smoke test. A phase is not done while any
of these fails. New behaviour with logic in it (snapshot store, layout persistence and clamping,
glyph computation, transition clock, lobby window) gets unit tests; purely visual work is verified
by screenshots, because a test of a colour proves nothing.

## Risks

| Risk | Why it matters | Plan |
|---|---|---|
| One root Canvas with swapped content | R3F expects a stable tree; swapping scenes can leak GPU memory | A single content slot with explicit dispose on swap; the Debug panel shows geometries and textures counts; a manual swap-100-times check in Phase 1 |
| Continuity between Scene and Session | The player's `ReplayPlayer` mutates the loaded scene graph | The Scene view never mutates the GLB; the Session view clones it once for the player, and the Scene view's copy stays pristine so going back is clean |
| Snapshot capture | Needs a finished frame and must not capture a replay mid-motion | Capture only from the Scene view, after framing, once per hash |
| Lobby request cost | 13 requests on open | Bounded, visible-tab only, cached by TanStack Query; verified in the network panel |
| Transition complexity | Interruptible camera moves are easy to get subtly wrong | One clock, one pose lerp, tested with a unit test that interrupts mid-way |
| Trace cost on weak GPUs | It is always on screen | Measured; point count and `dpr` reduce automatically if frame time exceeds budget |
| Ported inspector logic | I have not read it in detail yet | Phase 6 starts by reading it; scope of that phase may change after |
| Persisted panel layout | A saved position can be off-screen after a monitor change | Clamped on every load and on window resize; Reset layout always available |
| Breadth | This touches nearly every file | Phases end in something visible; each is a separate commit so any can be reverted |
